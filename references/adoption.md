# 首次或渐进接入

<a id="adoption"></a>

用户要求采用治理机制、把检查接入本地或 CI 时读本参考。普通功能任务复用目标既有入口；只读评审、一次性诊断和仅初始化元数据不走完整采用流程，元数据初始化按 [Skill §3.0](../SKILL.md#3-改动型任务走同一循环) 交付。当前请求与已接受决定共同约束实施范围，元数据不是许可。

本参考说明接入顺序与验收条件，不替目标项目选择参数。发布规则与工具保证的准确性由本 Skill 维护者负责；目标事实、owner、语料、命令、配置、权限、执行和报告由采用方负责。机制记录与各域参考提供具体条件、依赖和例外。

## 1. 触发与状态 owner

<a id="adoption-scope"></a>

只有当前请求要求采用治理机制或把检查接入本地/CI 时，才进入本流程。请求只涉及功能、修复、只读评审或解释时，直接复用目标已有入口，不生成采用决定。

状态是否启用、何时初始化及保存位置由 [Skill §3.0](../SKILL.md#3-改动型任务走同一循环)决定。沿用唯一 owner，不为采用另建同权威记录；没有持久状态需求的单会话决定可留在本次交付。

**完成判据。** 本次请求是否要求采用有明确结论；状态记录指向唯一既有 owner，或明确记录不启用状态协议及其依据；拟议范围能逐项对应当前请求，且没有为采用新建第二套状态记录。

## 2. 核实目标事实

<a id="adoption-target-facts"></a>

读取当前请求、既有验收、项目规则、唯一事实/状态 owner、工具链、脚本和 CI。把三类变更面分别绑定到目标文件或请求：当前已有的内容、本次接入将新增的文档/决定/配置/证据、以及之后必需的变更面。拟议路径不是已有事实；无法绑定的项目单列为未知，不写成现状。

对照 [Skill 第 4 节](../SKILL.md#4-按变更面读取参考)和[文档接入说明](documentation.md#migration)的触发条件检查这些变更面，其他域按各自触发索引读取。记录实际执行过的命令、实际退出码和原输出位置；复合命令只有总退出码时不编造子命令退出码。核对固定依赖的准备方式，以及检查内部安装、scratch、缓存和远端效果是否在授权范围内。

适用但缺少工具、依赖、语料、权限或 CI 接入时判为**触发但阻塞**：写明缺什么、已尝试什么、影响哪个验收条件、最小解阻动作。**不适用**只用于目标确实不存在该触发面，并写明判据与重新激活条件；缺工具、缺权限或尚未接入 CI 都不是不适用。

**完成判据。** 每个变更面都绑定到文件、请求或单列未知；每项相关机制有触发、阻塞或不适用分类及事实依据；实际命令与退出码已记录；依赖安装、scratch、缓存和远端效果的授权边界有结论；没有把缺失前提改写成不适用。

## 3. 适配参数并记录采用决定

<a id="adoption-decision"></a>

按 Skill 第 5 节读取命中机制的完整记录及其对应参考小节、依赖和例外。[文档迁移决定](documentation.md#migration)覆盖事实归属、状态复用、文档预算、完整语料和本地/CI 接线，是起点而非封闭清单；双语、API/示例、生成页、Note/归档、发布等分支按目标实际变更继续读取对应参考。领域细节留在原参考，采用决定只链接位置。

为每项要求确定目标 owner、路径、语料、阈值、工具链、现有命令和权限。来源案例值和示例阈值不是默认参数；已有合规内容仍可能需要持续检查。

在第 1 节选定的位置逐项记录一条可核对的决定链：目标事实与位置 → 机制 ID 及已发布决定的位置与依赖 → 保留的义务、例外与目标参数 → 检查或语义评审责任人及实际或待建入口 → 前提与权限 → 拒绝与精确恢复方式 → 状态。状态用**待接入**、**已接入且待复验**、**触发但阻塞**或**不适用**。

检查配置只登记命令，例如 `{"checks":{"项目检查名":"目标已有命令"}}`，以 `governance check <repo> --policy <仓内路径>` 执行；新初始化使用默认 policy。清单不复制需求、进度或验收，也不把 `governance check` 自身登记为其中的命令。持久规则的入口、执行者与拒绝证据按[持久规则准入](decisions.md#durable-rule-admission)核对；不能机械校验的语义判断单列评审程序。

机制记录与正文冲突、独立条件或分类不清，或无法在不削弱作用的前提下落地时，记录具体机制、原句/字段、目标影响和未决，交本 Skill 维护者核对并修正对应记录。影响验收的未决保持阻塞，不以猜测或将不同实现声明为等价来替代依据。

**完成判据。** 每项已触发要求都有完整决定链，或带有依据的阻塞/不适用结论；标为**已接入且待复验**的有真实入口和待补的验收证据，标为**待接入**的写明缺失入口；冲突项有具体记录并已升级；检查配置只含项目命令且不含自调用；决定没有分散到第二个权威位置。

## 4. 接受采用决定

<a id="adoption-acceptance"></a>

实施前由项目负责人或独立评审接受决定。接受者从目标实际变更面、路由和所读参考的条件反查遗漏，再直接阅读机制记录与参考正文，核对每项决定的事实、义务/例外、依赖、执行与评审责任、权限和原始报告；决定摘要、引文字面匹配、计数或 `verify` 通过都不能替代语义核对。

每项必需义务都必须有处置；影响验收的未决、冲突或驳回使整体决定不能接受。接受记录沿用第 1 节选定的位置，包含接受者及其权限、时间、决定版本和原始证据。接受者就是项目已有的负责人或独立评审，不另设角色或强制表单。保留原报告与失败；事后修正不追认原验收。

**完成判据。** 接受者、权限、时间、决定版本和原始证据可核对；每项必需义务已处置；没有影响验收的未决、冲突或驳回；实施不早于接受记录。

## 5. 实施：配置、接线与回归

<a id="adoption-wiring"></a>

从这里开始假定决定已被接受，原有行为验收不变。

**5.1 重读与配置。** 核对当前请求和已接受决定，读取本次变更触发的参考小节；事实变化时更新同一决定。保持既有脚本与状态归属，按已接受前提准备固定依赖和完整受检语料，阈值使用项目已确认的参数。

**5.2 同入口接线。** 开发者和 CI 调用同一顶层检查，保留原安装、矩阵及其他义务。把项目自己的检查写入清单，顶层 `governance check` 入口不写回自身，非零退出必须传播。缺远端目标或权限时准确保留该层阻塞，不把工作流文件当作远端强制；只有已获对应授权的隔离目标才能实测平台设置。

**5.3 真实变更与回归。** 完成应用/文档任务。每条已接受的可机械不变量都在同一共享入口保留正常与无效断言，临时探针不能替代后续 CI 所需的回归检查。语义义务由已指定的评审者核对，计数通过不抵销内容或适用性错误。

**完成判据。** 本地顶层入口真实存在并已运行；要求接入 CI 时，其步骤调用同一命令并继承退出码；触发的平台要求已在获授权的隔离目标上观察到，否则保留该层阻塞。检查配置只有命令且不递归；每条机械不变量在共享入口有正常与无效两类断言；每条语义义务有具名评审者。

## 6. 正常、拒绝与精确恢复收据

<a id="adoption-receipts"></a>

从同一入口观察三次结果：正常通过；真实破坏某项义务后被拒绝并返回非零退出；精确恢复后再次通过。把原始 stdout/stderr、实际退出码、注入与恢复命令、相关文件哈希存入目标已有证据位置；没有位置时使用本任务获准的输出位置，已启用状态协议时归到唯一 owner 所属的证据目录。采用决定或当前交付只链接原输出与结论，不复制同权威报告。

使用已批准的 scratch/缓存范围，日志不写秘密；保留可复核的收据后再清理一次性探针，不能把唯一证明日志也删掉。按 Skill 第 3.6 节交付，数值与诊断从原日志引用，不靠回忆改写。

本地执行、CI 运行、平台强制和人工审批是四类证据，分别记录：检查器存在不等于 CI 运行，本地失败不等于服务端拒绝，工作流文件不等于合并阻断。远端设置只在明确授权的隔离目标上实测；当前验收需要但未观察到的层级标为未验证，缺前提时写明阻塞，不把未触发的层级强加到任务。

**完成判据。** 同一入口的正常、拒绝、恢复三次观察都有实际退出码和原输出位置；拒绝由真实义务破坏触发，恢复后相关字节与注入前一致；收据位置、scratch/缓存范围和清理动作已记录，清理后结论仍可复核；每条证据标明所属层（本地、CI、平台或人工）。

## 7. 冷接续与采用完成

<a id="adoption-continuation"></a>

按 [Skill §3.0](../SKILL.md#3-改动型任务走同一循环)已启用持久状态、需要跨会话继续时，新会话从 Skill、唯一 owner、已接受决定、原收据和当前请求继续真实变更，重新评估触发要求，保留旧行为与原失败。先核对仓库和当前请求，记录与事实冲突时以仓库为准，不执行已撤销的动作。按[交接](agent-workflows.md#aw-11)与 Skill 第 3.6 节更新唯一 owner；单会话且未启用状态协议时，在当前交付报告本次结果与原证据，不为满足交接判据另建状态。

采用完成须同时满足：行为符合原验收；每项已触发义务均已落实，所有影响验收的未落实、阻塞或争议已解决；正常、拒绝、恢复在同一入口观察到；实际接入层级（本地、CI、平台）符合本次验收且如实记录；报告和必要的交接准确。报告实际命令、退出码、原输出位置及安装、临时写入或远端效果，区分观察、推断与未验证项。缺任一必需条件仍未通过，把缺口写成理由不构成通过，事后修正不追认原验收。

**完成判据。** 上述五项条件各有可核对的证据位置，没有影响本次验收的未解决项。需要跨会话接续时，下一位执行者能仅凭 Skill、唯一 owner、已接受决定、原收据和当前请求继续下一步；无持久状态需求的单会话采用以当前交付及证据验收，不强建 owner 或新会话。
