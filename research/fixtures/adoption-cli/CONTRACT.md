# 本地任务清单 CLI 契约

本文件说明验收对象，不维护开发状态或下一动作。仓库开发状态归根目录 `PROJECT.md`。

## 数据与接口

- Node.js >=22.19.0，ESM，仅使用 Node 内置模块。
- 入口是 `bin/tasks.mjs`。`TASKS_FILE` 指定持久文件；未指定时使用当前工作目录的 `tasks.json`。
- 文件是 JSON 数组，记录恰为 `{id, title, status}`。id 为唯一正安全整数，title 为非空白字符串，status 只能为 `open` 或 `done`。
- 成功退出 0，仅在 stdout 输出一个 JSON 值。错误仅向 stderr 给出诊断，stdout 为空。

## 命令

| 命令 | 可观察结果 |
|---|---|
| `add "标题"` | 去除首尾空白，保留中文、内部空格和引号；id 从 1 开始，以已有最大 id 加 1 分配；保存后输出新 `open` 任务 |
| `list` | 按 id 升序输出 `open` 任务数组 |
| `list --all` | 按 id 升序输出全部任务数组；重复 flag 属于多余参数 |
| `done <id>` | 将已有任务置为 `done`，保存并输出该对象；重复操作不新增记录 |
| `reopen <id>` | 将已有任务置为 `open`，保存并输出该对象；重复操作不新增记录 |

ID 参数采用 `[1-9][0-9]*` 的十进制形式且必须在安全整数范围内。flag 不作为标题内容解释，`add` 不接受 flag。数据文件缺失时，`list` 输出 `[]` 且不创建文件；`done` 和 `reopen` 拒绝不存在的任务。

## 拒绝、恢复与不变量

- 无效命令、flag、缺少/多余参数、空标题、非法或不存在的 id 均退出 2，保留原数据字节。
- 最大 id 已达 `Number.MAX_SAFE_INTEGER` 时，`add` 退出 2，不把不安全整数写入文件。
- JSON 损坏、非数组根、记录字段错误、重复 id、非法 status、空白标题等均退出 1，不能覆盖或“修复”为新空数组。
- 不同进程应读到上次保存的记录；列表排序不改变其他记录的含义。
- 验收分别覆盖正常状态转换、拒绝后数据不变、修复后的恢复。错误文案和 JSON 排版不作为契约。
- 只支持单进程本地使用；不提供并发写、崩溃原子性、服务端、多用户或同步保证。
